Tokeny CLAS-5

Claude Code · projekt alpha · serwer Linux

Ile tokenów zużywa praca Claude Code nad projektem alpha, dzień po dniu, według modelu i źródła. Koszt jest liczony w jednostkach wejścia. Każdy token waży tyle, ile w cenniku Claude: odczyt z pamięci podręcznej 0,1, zapis 2, odpowiedź 5. To proporcje do porównań, nie złotówki.

Zużycie dzienne według modelu

Jednostki są takie same dla każdego modelu, ale cena za token nie. Fable kosztuje więcej niż Opus, a Sonnet i Haiku wyraźnie mniej. Realny udział Fable w limicie jest więc większy, niż pokazuje wykres. Dzisiejszy słupek jest jaśniejszy, bo dzień jeszcze trwa.

Kontekst na wywołanie w głównej sesji

Każde wywołanie modelu czyta cały dotychczasowy kontekst rozmowy, więc długa sesja oznacza drogie wywołania. Świeża sesja zaczyna od około 90 tys. tokenów. Po 300 tys. Claude Code streszcza rozmowę. Nowa sesja na nowe zadanie trzyma tę linię nisko.

Dzień po dniu

Źródło: zapisy rozmów Claude Code projektu alpha na serwerze Linux (~/.claude/projects). Komputer z Windows i Cowork mają własne zapisy, więc ich tu nie ma.

Odświeżanie: codziennie. O 04:30 UTC cron serwera uruchamia tools/odswiez_tokeny.sh: monitor tools/zuzycie_tokenow.py --stan liczy dni i wypycha plik stan.json (same liczby) na gałąź tokeny-dane publicznego repo. O 05:00 UTC rutyna Cowork przepisuje go do bazy tej strony.

Wagi jednostek: wejście 1 · zapis cache 5 min 1,25 · zapis cache 1 h 2 · odczyt cache 0,1 · wyjście 5. Dni starsze niż 14 są zamrożone w runs/tokeny/stan.json, bo Claude Code kasuje zapisy po 30 dniach.

Zasady oszczędzania i pierwszy pomiar: docs/rag/12_zuzycie_tokenow.md.
